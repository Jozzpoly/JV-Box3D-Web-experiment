## 5. Compatibility verdict — donors agree on semantics more than on coordinates

The donor conflict is now narrower than before JV_CORE intake.

### Strong corroboration

JURE and JV_CORE independently support the same architectural lesson:

- mechanical relations are first-class;
- each relation endpoint has owner-local truth;
- a coherent wishbone should be represented as one semantic mechanical unit;
- authored/visual ownership must not be inferred from an arbitrary whole-body parent or stale metadata;
- neutral relation truth must stay separate from runtime dynamics/contact policy.

This makes independent owner-local frames and an explicit relation graph stronger than either donor alone.

### Important non-corroboration

JV_CORE **does not** upgrade JURE's current X-min outboard candidates into accepted ball-joint centers. G-RIG is sealed without claiming final exact physical mating coordinates. Therefore those coordinates remain Owner-open.

Likewise, JURE's use of a `carrier` concept/name cannot be lowered by name into a new extra physical body. For M6-compatible semantics it must map to the actual knuckle/upright role, or be rejected for that fragment.

### Schema consequence

The overlap is still strong enough for a **narrow lowering/adaptation seam**, not for a shared schema:

1. coordinate-system identity must be explicit; Y-up/right-handed alone is insufficient;
2. lowering full JURE frame orientation to only a primary axis may be lossy;
3. provenance/source binding must survive lowering where decision-relevant;
4. Web should encode only fields required by the selected front mechanical fragment;
5. Native source structs/configs are evidence, not a consumer format.

Therefore: **no unified JURE/JV_CORE/Web schema and no direct `RigDocument` or Native config runtime intake.**
